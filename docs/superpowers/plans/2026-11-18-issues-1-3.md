# Issues #1–#3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keine verlorene Eingabe bei vollem Speicher, Start trotz gesperrtem Speicher, Prototypen durch Theme-Prüfung der echten App ersetzt.

**Architecture:** #2 in der DOM-freien Persistenzschicht (`createRepo`), #1 in `app.js` auf #2 aufbauend (`askDialog`), #3 nur Werkzeuge/Doku plus ggf. Theme-CSS.

**Tech Stack:** Vanilla JS ES-Module, Node-Tests (`node tests/run.mjs`), Playwright-core/Firefox (`tools/verify-*.mjs`).

**Spec:** docs/superpowers/specs/2026-11-18-issues-1-3-design.md

## Global Constraints

- Nie `window.prompt`/`confirm`/`alert` — Rückfragen nur über `askDialog({title, message, buttons})` (app.js).
- `js/persistence.js` bleibt DOM-frei; `store.js` importiert weder persistence.js noch dom.js.
- Synchrone `test()`-Helfer lassen async-Tests fehlschlagen → Tests synchron schreiben.
- Gewerk-Farben `--gw-*`/`--gw-t-*` nicht anfassen; jedes Theme braucht beide Dunkel-Scopes.
- Version nicht stempeln, nicht pushen.
- Gestartete Browser/Server am Ende beendet; keine Subagenten-Unteraufträge.

## Review Focus

- Speicher wirft schon beim LESEN (Privatmodus) → App zeigt Erststart-Dialog, kein `pageerror`.
- Speicher voll nur für den Plan-Schlüssel, Projektwechsel → Dialog; «Abbrechen» lässt Projekt UND Eingabe stehen.
- Aufrufer von `open()` (Projektmenü ~1287, Neu ~1360, Import ~1263, Sync ~578/620, Autostart ~147–187) laufen nach «Abbrechen» nicht weiter (kein halb geschlossener Dialog, kein falscher aktiver Projekt-Index).
- Sync-Update desselben Projekts (`uebernehmen`) zeigt NIE den Dialog (kein Wechsel).
- Ein Theme, das in der App bricht, wird als Fehler gemeldet — nicht als «Prototyp übersprungen».
