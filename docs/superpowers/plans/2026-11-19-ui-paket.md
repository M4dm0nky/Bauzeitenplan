# UI-Paket Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die acht Bedienschwächen aus dem Review beheben, jede mit einer Prüfung, die vorher rot ist.

**Architecture:** Kleine, getrennte Eingriffe in gantt.js/live.js (Start, ⚠, Tooltip), table.js/bedarf.js (leere Zustände), index.html/app.js (Zoom-Knopf, Drucken), print.css/print.js (Einpassen), base.css (Handy-Kopf).

**Tech Stack:** Vanilla JS ES-Module, Node-Tests (`node tests/run.mjs`), Playwright-core/Firefox (`tools/verify-*.mjs`).

**Spec:** docs/superpowers/specs/2026-11-19-ui-paket-design.md

## Global Constraints

- Nie `window.prompt`/`confirm`/`alert`; Rückfragen über `askDialog`.
- Symbole statt Textkürzel; farbige Statusanzeige; Gewerk-Farben `--gw-*` tabu.
- Neue CSS-Klassen, die ein Theme gestalten muss → `needed`-Liste in `tests/run.mjs`; sonst über Tokens/`currentColor` (Muster `bz-bereit`).
- Jedes Theme: beide Dunkel-Scopes. Kernmodule (live.js, ebene.js, schedule.js …) DOM-frei; neue Logik dort → Unit-Test.
- Was `tabIndex` trägt, reagiert auf Enter UND Leertaste.
- Synchrone `test()`-Helfer lassen async-Tests fehlschlagen.
- Prüfwerkzeuge: Knöpfe im Einrichten-Fenster brauchen vorher `#rail-ein` + Reiter-Klick. `?plan=leer` schaltet den Autostart ab.
- Version nicht stempeln, nicht pushen. Gestartete Browser/Server am Ende beendet. Keine Unter-Subagenten.

## Review Focus

- Start an einem Tag ohne Vorgänge MITTEN im Plan (nicht nur davor/danach) → nächster Tag mit Vorgängen, nicht der Planbeginn.
- Live-Kopfzeile und Zeilen-⚠ zeigen für denselben Zeitpunkt dieselbe Menge verspäteter Vorgänge.
- Handy-Kopf im Showablauf MIT Live-Kopfzeile: die Live-Kopfzeile zählt nicht zum Kopf, darf aber nicht überlappen.
- Druckvorschau bei schmalem Fenster (z. B. 1000 px) und beim echten Druck (`page.pdf` bzw. `emulateMedia('print')`): Druck bleibt 1:1.
- Zoom-Menü per Tastatur bedienbar (Enter/Leertaste öffnet, Escape schließt — `openMenu` kann das).
