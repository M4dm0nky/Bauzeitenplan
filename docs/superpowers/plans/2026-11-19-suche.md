# Suche «Schnell finden» Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Suchfeld in der Kopfzeile, Treffer anspringen und auswählen.
**Architecture:** DOM-freie Trefferrechnung in schedule.js (geteilt mit candidateGroups); UI in einem kleinen neuen Modul `js/suche.js` (rendert nur, meldet über Rückrufe nach app.js — Muster rail.js/bedarf.js); Sprung über vorhandene gantt/table-APIs.
**Spec:** docs/superpowers/specs/2026-11-19-suche-design.md

## Global Constraints
- Nie `window.prompt/confirm/alert`. Symbole statt Textkürzel. Was `tabIndex` trägt, reagiert auf Enter UND Leertaste.
- Kernmodule DOM-frei; neue Logik dort → Unit-Test. Synchrone `test()`-Helfer lassen async-Tests fehlschlagen.
- Neues Modul in js/ → `HUELLE` in sw.js (tests/run.mjs prüft beide Richtungen); neue Theme-Klassen → `needed`-Liste + alle fünf Themes (oder Tokens/currentColor).
- `setAnsicht()` bleibt der einzige Schreiber von ansicht/ebene/abschnitt.
- Kein `git stash`, keine Warteschleifen, nur Vordergrund-Läufe; Prozesse am Ende beendet. Version nicht stempeln, nicht pushen.

## Review Focus
- Treffer in einer zugeklappten Gruppe / unter einem zugeklappten Sammelvorgang → wird aufgeklappt und ist sichtbar.
- Showablauf: Treffer an einem anderen Showtag oder im anderen Abschnitt → Ansicht wechselt, Gantt UND Tabelle zeigen denselben Tag.
- `/` während man in einem Tabellenfeld tippt → tippt ein «/», öffnet nicht die Suche.
- Handy 390×844: 🔍-Knopf, Feld über der Kopfzeile, Kopf bleibt ≤ 300 px, Gantt ≥ 50 %.
- Umlaute/Groß-Klein («bühne» findet «BÜHNE»).
